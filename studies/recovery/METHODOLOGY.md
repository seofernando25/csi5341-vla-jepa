## Initialization and adaptation

The SmolVLM transplant initially inherits compatible action/world modules from the pinned `VLA-JEPA-Pretrain` artifact, then continues the legacy 10k weights. It does not inherit the full LIBERO-fine-tuned Qwen policy used by B16. The [paper appendix](https://arxiv.org/html/2602.10098v1#A2) describes 50k joint SSv2/DROID pretraining updates and learned latent/action tokens. Our newly added SmolVLM query-token embedding rows are initialized by native vocabulary expansion and remain frozen; four final decoder layers can adapt their output, but the query embeddings themselves cannot specialize. The [passive row audit](diagnostics/query_token_rows.json) confirms all 29 added-token rows are byte-identical between 2k and 5k and nearly equal to one another (coordinate RMS deviation 2.29e-5). The actual prompt uses three latent-token types repeated eight times each, followed by one embodied-action token repeated 32 times; the other added rows are unused in this recipe. Positional encoding still differentiates token positions; this does not prove conditioning collapse. The [pinned Qwen lineage audit](diagnostics/qwen_query_reference.json) finds changes in all four used query rows at both pretraining and LIBERO stages; the other 25 added rows are unchanged. This verifies specialization of the reference queries, without establishing the causal contribution or training corpus. This is a concrete recipe difference, not a demonstrated cause of failure. The public model card does not independently establish every pretraining detail.

Two legacy-loader, zero-initialized, training-frame-only probes add 3,840 query-residual parameters at input or before decoder layer 28. Both exactly preserve that loader’s measured action/world losses and receive finite nonzero action gradients, with no optimizer update. Batch-one peak allocations are 6.93 GiB (input) and 5.17 GiB (late), versus 5.15 GiB without a probe. These are gradient diagnostics, not training-budget estimates or successful policies. Input adaptation requires backward through earlier frozen layers; a future memory-limited study must explicitly register accumulation and count actual optimizer updates, because native training steps count microbatches.

The registered follow-up tests input-query adaptation together with broader decoder adaptation, preserving data, preprocessing, objectives and action semantics. Their effects cannot be isolated in this coupled study. A matched corrected-input root remains required to assess n0008's architecture. Native crop reduction would require separate processing registration and retraining; it must not enter this running study.

## Inference precision amendment

The [reversible buffer audit](diagnostics/rotary_buffer_precision.json) identifies a second pipeline mismatch. Native recovery training retains FP32 rotary-position frequency buffers, but the inference loader globally casts them to BF16. These nonpersistent buffers are absent from saved weights; weight-hash verification cannot detect this difference. On the fixed training frame (episode 53, frame 40, seed 92000), changing only these two buffers raises action loss from **0.046005 to 0.061796**; restoring their original FP32 values restores the loss exactly. Weighted world loss changes negligibly. This is one-frame evidence, not a success estimate.

The [separate inference registration](native_rope_registration.json) preserves the original FP32 values **before** the BF16 parameter cast; upcasting rounded values would not repair them. Legacy behavior remains the loader default, and cloud training, architecture, inputs, solver, seeds and frozen RSI remain unchanged. The fixed 5k checkpoint is compared under both modes on the same local GPU and ten first development states. The first paired task-1 trace fails in both modes (18 versus 26 gripper transitions), so this defect alone has not rescued that case. Final trials remain reserved.

Earlier action/noise/gradient/query-probe diagnostics loaded through the BF16-buffer inference path. Their recorded values remain attributable to that path; they must not be presented as exact native-training precision. The new persistent query-source check uses native FP32 buffers, restores every inherited tensor exactly, preserves initial native losses, serializes its configuration, and obtains finite gradients through nonreentrant checkpointing. It adds only four 960-dimensional query residuals (3,840 parameters), with no optimizer update or policy export. This prepares a separate adaptation test; it is not a trained model.

A [task-instruction audit](diagnostics/task_instruction_mapping.json) confirms that all ten dataset instructions match the simulator strings exactly. Their numeric task IDs use different permutations; task-level analyses must join by instruction rather than by numeric ID. No instruction mismatch was found.

The earlier cloud 5k result was 0/10 on RTX5090; numerical differences can compound in closed-loop simulation, so these hardware results are not pooled. The native-precision defect remains verified but has not explained the overall failure.

Batch-eight query forward/backward with synthetic FP32 AdamW moment buffers also passes on the RTX3090, at **20.10 GiB** peak framework allocation, using `PYTORCH_ALLOC_CONF=expandable_segments:True`.
